# ELC 电量监视 · 界面设计规范

> 交互预览：`design/design-system.html`（可切换亮/暗主题）
> 适用：WPF / .NET 8 桌面托盘工具，440px 无边框窗口

---

## 1. 设计目标

这是一个「低头看一眼就走」的工具，不是需要停留的仪表盘。四条原则决定所有取舍：

| 原则 | 具体落地 |
|---|---|
| **数字优先** | 百分比 27px/600 是卡片唯一视觉重心，其余元素全部退让到 12px 次要色 |
| **状态可辨** | 颜色 + 图标 + 文字三重编码，不靠色相单独承载语义（色弱可辨） |
| **零学习** | 列表、开关、分段控件、步进器全部照搬 Windows 用户预期，不发明交互 |
| **一眼全局** | 底部固定显示「最低 X%」，多设备时最紧张的那台自动置顶或高亮 |

### 排版

| 层级 | 字号 | 字重 | 其他 |
|---|---|---|---|
| 卡内百分比 | 27px | 600 | 行高 1，字距 −0.5px，**tabular 数字** |
| 设备名 | 14px | 600 | 单行，尾部省略 |
| 设置项名 | 13px | 400 | — |
| 窗口标题 | 14px | 600 | — |
| 副信息 / 状态 | 12px | 400 / 600 | 状态用 600 |
| 分组标题 | 11px | 600 | 字距 0.6px，`--text-3` |

字体栈：`Microsoft YaHei UI → Segoe UI Variable → Segoe UI`
数字单独用 `Segoe UI` 渲染可拿到更好的 tabular 对齐。

### 间距 / 圆角 / 描边

- 间距基准 4pt：4 / 8 / 10 / 12 / 16 / 20 / 24。卡内 13–15，卡间 9，设置分组间 14
- 圆角：窗口 14 · 卡片 14 · 输入与分段 8 · 开关胶囊 9 · 进度条 4
- 描边：**一律 0.5px**。常规 `--border`，强调 `--border-strong`，未适配卡片用 `dashed`
- 窗口：440 × 自适应，最小 380×360，内容超 620 后卡区滚动

## 3. 三屏结构

### 3.1 主界面

```
┌ 标题栏 44px ──── logo 26 + "电量监视" ──── 刷新/设置/最小化/关闭 28×28 ┐
│                                                                        │
│  ┌ 设备卡片 × N ────────────────────────────────────────────────┐    │
│  │  设备名 14/600                              [ 27/600 % ]      │    │
│  │  ▓▓▓▓▓▓░░░░░░░░░░░░  ← 8px 进度条，20% 处有预警刻度          │    │
│  │  2.4G 无线 · 12 秒前更新            [图标] 低于预警线 20%     │    │
│  └──────────────────────────────────────────────────────────────┘    │
│                                                                        │
└ 底部固定条 ──── 最低 18% · 17:11 刷新 ───────────── 立即刷新 ─────────┘
```

- 名称与数值**同行两端对齐**（先抓设备再抓数值），进度条横跨全宽给量化感
- **预警刻度**：在你设的阈值百分比位置画一条 2×13px 竖线，让数字有参照物
- 状态标记**只在需要提醒时出现**（偏低/危险/充电中/无应答），正常状态留空 —— 空比「正常」更安静
- 底部把「最低电量」和「刷新时间」合并成一行，不额外占空间
- 「立即刷新」从图标区移到底部右侧做文字链接，成为可发现的主动作

### 3.2 设置页

独立视图，用标题栏返回箭头出入，**不再与列表共用同一块空间**。四个分组卡片：

| 分组 | 内容 | 控件 |
|---|---|---|
| 读取 | 刷新间隔 / 唤醒后立即读取 | 分段（30秒·1分·5分）+ 开关 |
| 提醒 | 一级提醒 / 二级提醒 / 提示音 | 步进器 + 开关 |
| 启动与退出 | 开机自启 / 点关闭时行为 | 开关 + 分段 |
| 外观 | 主题 | 分段（浅色·深色·跟随系统） |

- 底部**固定操作条**（不随滚动）：左「恢复默认」，右「取消 / 保存」
- 刷新间隔由裸 TextBox（要手输秒数）改为分段控件 —— 降低输入负担
- 阈值由两个裸 TextBox 改为步进器：单击 ±1，长按连续，Shift 单击 ±5，范围 5–50%

### 3.3 空状态

线稿插画（76×52）+ 主文案 14/600 + 说明 12px + 描边主按钮「重新扫描」。保留标题栏可用，不做整屏灰化。

### 3.4 未适配设备卡片

虚线边框、虚线空槽代替进度条、数值位显示 `--`、右下「导出报告」文字链接。**刻意降低视觉权重但不隐藏** —— 让分发对象知道程序认出了设备，只是读不到。

### 3.5 托盘图标

**方案：暗轨道 + 电量弧的进度环。**（2026-10-20 第三版）

| 元素 | 规格 |
|---|---|
| 画布 | 32 × 32，`Format32bppArgb`，**完全透明** |
| 形状 | 圆环，笔宽 10% 画布（3.2px），环视觉直径约 26px |
| 编码方式 | **弧长 + 颜色双重编码**：从顶部顺时针扫过 `percent × 3.6°` |
| 弧色 | 电量色阶 `HSV(0°→120°, S=0.72, V=0.86)`：0% 红 → 50% 黄 → 100% 绿 |
| 轨道色 | 随主题 —— 深色托盘 `#4A505A`，浅色托盘 `#E2E5EA` |
| 离线 | 只有灰轨道环 `#8A929E`，**不画弧**（没有电量可表示） |
| 充电 | 不做特殊标记 —— 具体百分比与充电状态在 tooltip 和主窗口 |

**为什么不用纯色环**（第二版方案）：自检数据是硬证据 ——

| 样式 | 25% 覆盖率 | 75% 覆盖率 | 结论 |
|---|---|---|---|
| 纯色环 | 27.4% | **27.4%** | 覆盖率完全相同，只有颜色在变。8% 和 25% 都是橙红，看不出差别 |
| 进度环 | 28.1% | 29.5% | 覆盖率随电量变化，弧长真的在编码电量 |
| 电池胶囊 | 17.7% | 22.5% | 填充面积随电量变化，但细节最多、最不"简约" |

进度环保留了圆环的简约（无内部细节，任何缩放都清晰），同时把电量多少画了出来 —— 这是三个方向里唯一同时满足「简约」和「看得出电量」的。

**备选样式**（`tools/IconPreview` 里实现过，未实装）：`ring` 纯色环（用户最初的参考图样式）、`battery` 电池胶囊。
切换只需改 `IconRenderer.Create` 里的一行：`DrawArc(rect, -90, percent * 3.6f)` ↔ `DrawEllipse(pen, rect)`。

**自检基线**：进度环覆盖率应随电量上升（约 28% → 30%），主色在低电量时为轨道灰、高电量时为绿 `#8CDB3D`。**覆盖率不随电量变化 = 弧没画上。**

调参数流程：`dotnet run --project tools/IconPreview -- design/icons` → 看 `design/icons/preview.png` → 确认后同步回 `IconRenderer`。

**注意：轨道色依赖主题，换主题必须 `SyncTrayIcons()` 重画**，否则深色托盘上会留下浅色轨道（看不见）。

#### 刷新动画

手动刷新（托盘双击 / 托盘菜单 / 主窗口按钮）时，图标播放**短弧绕圈旋转**：10 帧 × 58ms ≈ 580ms 一圈，最短播满 640ms。后台定时刷新不播。

这一段曾经做过**脉冲呼吸**和**拖尾扫过**两个备选，用户实测反馈「跟旋转没什么区别」—— 确实如此，32px 经托盘缩放、再叠加系统约 60ms 的更新节流，细微的形状差异全被吃掉。逐帧数据也印证了：扫过的墨量变化只有几个百分点。**在小尺寸 + 低频刷新下，只有位置变化（旋转）是明确可辨的**，明暗与拖尾都不行。已移除，不做设置项。

### 3.6 程序主图标

主图标 ≠ 电量图标。电量图标（上节）承载数据，主图标承载**品牌**，两者必须能一眼区分：

| 元素 | 规格 |
|---|---|
| 底 | 纯色圆 `#2563EB`（= UI accent，与主窗口 logo 同色） |
| 图形 | **270° 白弧**，顶部起点、缺口在左上，笔宽 10.5% 画布，圆头端点 |
| 弧半径 | 30% 画布（外缘距圆底边约 4.5px） |

为什么是白弧而不是电池：电量环是这个产品的核心视觉符号，主图标沿用同一个符号形成品牌记忆 —— 用户在托盘里看到「蓝底白弧」就知道是 ELC，看到「彩色弧环」就知道是电量。旧版主图标的问题：藏蓝渐变 + 一个 7px 高的迷你电池，任何尺寸下都糊成一团，像 Windows 的「未知设备」。

`app.ico` 由 `tools/IconPreview` 生成（16/24/32/48/64 五尺寸 PNG 内嵌），`ElcBattery.App.csproj` 的 `ApplicationIcon` 指向它 —— **exe 文件图标和运行时托盘主图标来自同一份设计**。改主图标后：重跑工具 → 重新编译。

## 4. 交互规范

### 键盘

| 快捷键 | 行为 |
|---|---|
| `Ctrl + R` | 立即刷新 |
| `Esc` | 设置页返回 / 主界面最小化到托盘 |
| `Ctrl + ,` | 打开设置 |

Tab 顺序：窗口按钮 → 设备卡片 → 底部刷新。焦点环 2px `--accent` + 2px offset，始终可见。

### 动效

| 场景 | 时长 / 曲线 |
|---|---|
| 视图切换 | 位移 16px + 透明度，180ms `cubic-bezier(.2,0,0,1)` |
| 数值变化 | **无动画**，直接替换（刷新频繁，动画会变噪音） |
| 进度条 | 宽度 240ms ease-out；语义色 120ms 交叉淡入，避免红绿闪烁 |
| 手动刷新 | 图标旋转一圈 600ms；自动刷新无动画 |
| 开关滑块 | 200ms ease |

全部尊重系统「减少动画」设置，降级为瞬时切换。

### 反馈时机

- **读取失败**：卡片内 `--` + 副信息说明原因，不弹窗。连续 3 次失败才升为托盘气泡一次
- **点关闭 → 最小化**：首次执行时弹一次性气泡「已最小化到托盘」，之后静默
- **保存设置**：按钮文字变「已保存」600ms 后复原，不弹对话框

## 5. WPF 实现要点

| 问题 | 做法 |
|---|---|
| **主题切换** | 现有 `App.xaml` 画笔是 `StaticResource`，切换不会生效 → 改 `DynamicResource`，两套字典放 `Themes/`，运行时替换 `MergedDictionaries` |
| **数值不跳宽** | `Typography.NumeralAlignment="Tabular"`；雅黑回退时数字单独用 `Segoe UI` |
| **图标** | 放弃 `⟳ ⚙ — ✕` 字符，改 `Path Data`（Geometry）。字符图标在不同 DPI 下基线漂移，且无法控制描边粗细 |
| **预警刻度** | 进度条 ControlTemplate 里加 `Border`，`HorizontalAlignment=Left` + `Margin` 绑定阈值；或用两列 `ColumnDefinition Width="*"` 按百分比分配 |
| **视图切换** | 两屏放同一 `Grid` 的两层，对 `TranslateTransform.X` 与 `Opacity` 做 `DoubleAnimation`。**不要用两个 Window** |
| **分段控件** | WPF 无原生控件 → `ListBox` + 自定义 `ItemContainerStyle` |
| **开关** | `ToggleButton` + 自定义 Template（Track + Thumb） |
| **窗口高度** | `SizeToContent=Height` 与最大化冲突 → 代码设 `Height = min(内容高, 620)`，超出由 `ScrollViewer` 接管 |

## 6. 落地顺序

三步**已全部实装**（2026-10-20）。

| 阶段 | 内容 | 状态 |
|---|---|---|
| 一步 | 状态语义色 + 图标换 Path + 数值 tabular + 预警刻度 | 已完成 |
| 二步 | 设置页拆独立视图 + 分组卡片 + 分段/开关/步进器 | 已完成 |
| 三步 | 暗色主题 + 空状态插画 + 未适配卡片形态 | 已完成 |
| 追加 | 托盘图标改版：透明底 + 描边大数字 | 已完成 |

**实装时做的两处偏离设计稿的决定**（都是功能优先）：

1. **刷新间隔用步进器，不用分段控件**。分段只有 30 秒 / 1 分 / 5 分三档，会丢掉配置里已有的任意秒数。步进器同样免手输，且不丢功能。
2. **弃用 DWM 磨砂背景**。实测 `SYSTEMBACKDROP_TYPE` 在本机把窗口染成了黑色（缺 `ExtendFrameIntoClientArea`），更重要的是磨砂色调由系统决定、会盖住主题色，让对比度不可控。改为主题实色。

**已移除的功能**：自定义托盘图标底图、窗口背景图、背景不透明度（19:02 用户确认删除）。三者都与「数值颜色必须可控」冲突 —— 花哨底图会让红/琥珀数字压在图案上直接失效，对比度无从保证。设置页的外观组因此只剩「主题」与「托盘刷新动画」两项。
